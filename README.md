# Trader Control Plane

ربات MT4 ماژولار، پایش زنده و کنترل ورود خودکار با داشبورد فارسی شیشه‌ای.

## اجرا روی لپ‌تاپ

پیش‌نیاز: .NET SDK 10، ویندوز و MT4. SDK 10.0.401 در این محیط داخل `.artifacts/dotnet` نصب شده؛ اسکریپت‌ها خودکار از آن استفاده می‌کنند.

1. تلگرام از فایل محلی `.env` خوانده می‌شود؛ مقادیر موجود حفظ شده‌اند. نام تنظیمات در `.env.example` است.
2. روی **`Start-Trader.cmd`** دوبار کلیک کنید. پنجرهٔ فارسی کوچک در وسط صفحه باز می‌شود، API را آماده می‌کند، سپس Bridge و مرورگر را باز می‌کند. اولین اجرا، پروژه‌های لازم را می‌سازد و ممکن است کمی طول بکشد.
3. برای بازکردن پنجره بدون شروع سرویس‌ها، از ریشه اجرا کنید: `Start-Trader.cmd --manual`. دکمه‌های «اجرای برنامه»، «اجرای پل» و «راه‌اندازی همه» در دسترس‌اند؛ اجرای پل ابتدا منتظر آماده‌شدن API می‌ماند.
4. داشبورد روی http://127.0.0.1:5080 است. [EA را نصب و بررسی کنید](docs/mt4-bridge.md). لانچر MT4 را نصب، باز یا به حساب وارد نمی‌کند. اجرای تازهٔ API همیشه با ورود خودکار متوقف است؛ لانچر مجوز معامله را فعال نمی‌کند. سرویسِ از قبل روشن، همان وضعیت قبلی خود را حفظ می‌کند.
5. «توقف سرویس‌ها» یا بستن پنجره با تأیید، فقط فرایندهای ساخته‌شده توسط همان لانچر را متوقف می‌کند؛ معاملات بروکر بسته نمی‌شوند. برای روشن‌ماندن سرویس‌ها پنجره را کوچک کنید. سرویس‌های از قبل روشن متوقف نمی‌شوند.

لانچر از فونت Modam پروژه و پنل‌های شیشه‌ای استفاده می‌کند؛ فرایندهای سرویس در پس‌زمینه اجرا می‌شوند. وضعیت پورت Bridge بدون اتصال آزمایشی TCP خوانده می‌شود تا نشست EA قطع نشود. بازبودن پورت، اثبات اتصال EA یا حساب نیست؛ وضعیت واقعی را در داشبورد ببینید. پورت‌های ثابت محلی 5080 و 8766 و پوشهٔ دادهٔ `data` استفاده می‌شوند؛ تنظیمات استقرار راه‌دور از این لانچر اجرا نمی‌شوند. گزارش‌ها در `data/launcher-logs` هستند.

بدون تغییر Execution Policy ویندوز، اجرای دستی در دو ترمینال هم ممکن است؛ API را اول اجرا کنید:

    scripts\dotnet.cmd run --project Api --no-launch-profile -- --environment Development
    scripts\dotnet.cmd run --project Bridge --no-launch-profile

API کلید محلی data/bridge.key را می‌سازد. توسعه‌ی بدون رمز فقط درخواست‌های loopback با Host محلی را می‌پذیرد.

## ساختار

- Domain: پارامترهای معتبر، محاسبات علّی EMA/ATR/ADX، ناحیه قیمت و موتورهای قابل جایگزینی.
- Application/Strategy: مسیر مشترک تحلیل زنده و بک‌تست؛ استراتژی، محاسبات و پارامترها جدا هستند.
- Application/Research: بک‌تست قطعی و انتخاب پارامتر روی آموزش، با آزمون زمانی جداگانه.
- Application: قرارداد بروکر، وضعیت اجرا، تنظیمات و ذخیره‌سازی.
- Trader.Protocol: فریم UTF-8 محدود، نسخه و شناسه‌ی درخواست.
- Infrastructure: gateway، SQLite، اجرای قابل تطبیق و outbox تلگرام.
- Bridge: Agent مستقل؛ اتصال خروجی به بک‌اند و اتصال محلی به MT4.
- Api: ورود امن، REST/SSE و رابط RTL در wwwroot.
- Trader.Launcher: پنجرهٔ کنترل محلی ویندوز؛ مستقل از انجین و بدون مجوز فعال‌سازی معاملات.

مسیر Named Pipe و jobهای دارای وضعیت static کنار گذاشته شده است. EA فقط Winsock خود ویندوز را import می‌کند.

## محافظت و محدودیت‌ها

- حجم بر اساس فاصلهٔ واقعی ورود تا استاپ، tick size/value در پول حساب و ذخیرهٔ کارمزد/لغزش محاسبه و رو به پایین نرمال می‌شود؛ حداقل لاتِ خارج از بودجه رد می‌شود و بازبینی قبل از سفارش حجم را افزایش نمی‌دهد.
- فیلتر EMA50/200 فاز H4، حد ADX، شکست و ری‌تستِ کندل بعدی، استاپ ساختاری/ATR و هدف با نسبت سود/ریسک خالص به مسیر مشترک اضافه شده‌اند. تنظیمات قدیمی خودکار جایگزین نشده‌اند؛ پیش‌فرض‌ها فرضیه‌اند، نه نتیجهٔ سودآوری تأییدشده.
- حفاظت پایدار Equity پیش‌فرض ۳٪ روزانه/۲۴ ساعت و ۱۰٪ کل دارد؛ مرجع بک‌اند و EA مستقل‌اند. بستن اضطراری فقط معاملات دارای Magic ربات و فقط با انتخاب صریح `CloseOwnedOnMaxDrawdown` است؛ پیش‌فرض خاموش می‌ماند.
- سهمیه‌ی روزانه فقط با تأیید سفارش مصرف می‌شود. نتیجه‌ی نامشخص پایدار و قابل تطبیق است؛ سفارش کورکورانه تکرار نمی‌شود.
- قطع ارتباط، بسته‌شدن معامله را تأیید نمی‌کند. معاملات قبلی پس از راه‌اندازی از بروکر بازیابی می‌شوند.
- توقف ورود، معاملات باز را نمی‌بندد. استاپ و تریلینگ مستقل EA باقی می‌مانند؛ خاموش‌شدن MT4 تریلینگ را متوقف می‌کند.
- UI داده‌ی مالی زنده ساختگی ندارد. فیلتر خبر فعال نشده؛ تحلیل اندیکاتوری و پرایس‌اکشن با پارامترهای بیرونی در C# اجرا می‌شوند.
- سقف پیش‌فرض EA یک درصد و ۵ واحد پول حساب است؛ تغییر UI محدودیت سخت EA را دور نمی‌زند.
- لغزش، گپ، کارمزد و رفتار بروکر مانع تضمین سقف ضرر یا سودآوری هستند.
- OrderSend و OrderModify خود MT4 همگام‌اند؛ انتظار شبکه حذف شده، اما تأخیر بروکر هنوز باید روی دمو آزموده شود.
- outbox تلگرام برای هر گیرنده رسید جدا دارد. قطع پاسخ پس از پذیرش پیام همچنان می‌تواند به اعلان تکراری منجر شود.

فونت‌های مدامِ ارائه‌شده در `Api/wwwroot/fonts` در هشت وزن TTF به داشبورد متصل شده‌اند. رابط فارسی RTL، پنل‌های شیشه‌ای و انیمیشن با پشتیبانی کاهش حرکت دارد.

## ولوم ریسک و انتخاب Auto

در صفحهٔ «معاملات»، ولوم پنج حالت **پایش بدون ورود، کم‌ریسک، متعادل، فعال، ریسک بیشتر** دارد. حرکت ولوم فقط پیش‌نمایش شروط و توضیحات را در کارت و پنل چارت عوض می‌کند؛ «اعمال حالت» تنظیمات را در SQLite ذخیره می‌کند و ورود خودکار را روشن نمی‌کند. وقتی ورود فعال است، تغییر هم در رابط و هم در بک‌اند مسدود است. تغییر هم‌زمان تنظیمات توسط اپراتور دیگر، اعمال پیش‌نمایش قدیمی را با خطای 409 رد می‌کند.

پایش بودجه/سهمیهٔ ورود جدید را صفر و مسیر اجرای سفارش را مسدود می‌کند؛ معاملات باز را نمی‌بندد و ریسک آن‌ها را حذف نمی‌کند. چهار حالت معاملاتی به‌ترتیب سقف درصد/مبلغ/ورود روزانهٔ `0.25% / 1 / 2`، `0.5% / 2 / 4`، `0.75% / 3 / 6` و `1% / 5 / 10` دارند. مبلغ به ارز حساب است و بودجهٔ کوچک‌ترِ درصد و مبلغ اعمال می‌شود. مقادیر و توضیحات در `Api/appsettings.json → RiskProfiles` متمرکزند؛ پیش‌فرض‌های پیشنهادی‌اند، نه پارامترهای سودآور اثبات‌شده. تغییر دستی شروط در تنظیمات پیشرفته، نام حالت ناسازگار را به «سفارشی» تبدیل می‌کند.

مرز انتخاب موتور Auto اکنون با `AutoSwitchAdx` از حداقل ADX ورود مستقل است: زیر حداقل ورود، سیگنال رد می‌شود؛ از آن تا مرز Auto، وجود ناحیهٔ معتبر مسیر پرایس‌اکشن را قابل انتخاب می‌کند و در نبود ناحیه موتور اندیکاتوری بررسی می‌شود؛ از مرز Auto به بالا اندیکاتوری اولویت دارد. مرز پیش‌فرض 45 و حداقل ورود حالت‌ها 25 تا 30 است. انتخاب موتور، به‌تنهایی دستور معامله نیست؛ تأیید EMA کلان، ری‌تست، استاپ/هدف خالص، اسپرد، حجم بروکر و حفاظت سرمایه همچنان لازم‌اند.

برای تنظیمات قدیمی Auto که پارامتر جدید را ندارند و حداقل ADX آن‌ها 45 یا بالاتر است، هنگام خواندن مقدار سازگارِ `min(100, MinimumEntryAdx + 1)` استفاده می‌شود؛ آستانهٔ ورود و بودجهٔ قبلی دست‌نخورده می‌مانند و ذخیرهٔ خودکار یا فعال‌سازی ورود انجام نمی‌شود. در حد نهایی ADX=100 فقط مرز اندیکاتوری قابل دسترس است. ذخیرهٔ فرم پیشرفته نیز baseline را بررسی می‌کند؛ قرارداد `POST /api/settings` اکنون بدنهٔ `{settings, expectedSettings}` می‌خواهد و فرم/درخواست کهنه به‌جای بازنویسی بی‌هشدار رد می‌شود.

حالت‌ها تایم‌فریم، هزینه‌ها، تریلینگ، افت سرمایه، مجوز حساب واقعی، نماد و تلگرام را تغییر نمی‌دهند و سقف سخت EA را دور نمی‌زنند. افزایش بودجه به‌تنهایی معاملات بیشتر یا سود بیشتر تضمین نمی‌کند. اگر حداقل لات بروکر از بودجه بیشتر باشد، ورود رد می‌شود. در پایش، برای بک‌تست باید ریسک، مبلغ و سهمیهٔ **فرضی مثبت** را در آزمایشگاه وارد کرد؛ این مقادیر به حساب زنده اعمال نمی‌شوند.

## پژوهش استراتژی

از بخش «آزمایشگاه استراتژی» داده بروکر را دریافت کنید یا فایل JSON حاوی کندل‌های صعودی و مشخصات کامل نماد وارد کنید. برای EMA200 فاز، پیش‌تاریخچهٔ بستهٔ H4 در `phaseCandles` لازم است؛ دریافت از بروکر آن را جدا می‌خواند. اسپرد، لغزش، کارمزد، سرمایه و ریسک فرضی قابل تنظیم است. بک‌تست قواعد مشترک تصمیم، تریلینگ بسته‌شدن کندل با Wilder ATR و توقف ورود بر اثر افت Equity را دارد؛ گپ، قیمت واقعی و نمونه‌گیری Tick هنوز می‌توانند نتیجهٔ اجرا را متفاوت کنند. پارامترهای تریلینگ/هزینه/افت سرمایه باید با EA نسخهٔ 3.10 یکسان باشند، وگرنه ورود مسدود است.

Kelly، خروج MAE/MFE، Mark Price مستقل و تعدیل funding/swap بدون داده و تعریف معتبر فعال نشده‌اند. سود تضمین نمی‌شود؛ پیش از حساب واقعی، دادهٔ معتبر، اعتبارسنجی خارج از نمونه و اجرای دمو لازم است.

جست‌وجوی پارامتر حداکثر ۱۶ ترکیب را روی آموزش بررسی می‌کند و ترکیب منتخب را روی بازه بعدی اعتبارسنجی می‌کند. حد افت سرمایه و حداقل معاملات آموزش اعمال می‌شوند. تنظیمات زنده خودکار تغییر نمی‌کنند. [قرارداد داده و مفروضات](docs/research.md).

## استخراج دانش از منابع NotebookLM

متن کامل [پرامپت JSON](docs/strategy-extraction-prompt.json) را در چت NotebookLMِ متصل به منابع خود قرار دهید؛ منابع مرتبط را انتخاب کنید و خروجی را برای ارتقای استراتژی برگردانید. پرامپت قواعد ورود/خروج، تعریف روند، حجم، ریسک، استاپ/تریلینگ، الزامات داده و شواهد را استخراج می‌کند و تعارض‌ها و موارد نامعلوم را جدا نگه می‌دارد. از NotebookLM نتیجه یا پارامتر سودآور ساختگی نمی‌خواهد. این استخراج، اثبات سودآوری یا مجوز معاملهٔ واقعی نیست.

## اعلان‌های تلگرام

در `.env` مقادیر `TELEGRAM_BOT_TOKEN` و `TELEGRAM_CHAT_IDS_0` را وارد کنید؛ برای گیرندهٔ دوم از `TELEGRAM_CHAT_IDS_1` استفاده کنید. در چت ربات `/start` بزنید یا اجازهٔ ارسال در گروه بدهید. رمز و توکن را در چت، Git یا فایل‌های قابل توزیع قرار ندهید. پس از تغییر این مقادیر، API باید دوباره اجرا شود. گزینهٔ تلگرام در تنظیمات داشبورد نیز باید فعال باشد.

پیام‌ها شامل عنوان فارسی، جهت، نماد، تیکت، حجم، استاپ و هدف هستند؛ برای بسته‌شدن، سود/زیان خالص گزارش بروکر اضافه می‌شود. قیمت اعلانِ ثبت سفارش «مرجع» است، نه ادعای قیمت پرشدن. زمان اعلان به UTC مشخص شده و متن پویا پیش از قالب HTML امن می‌شود.

صف SQLite و رسید جداگانهٔ گیرنده حفظ می‌شوند. زمان تلاش مجدد هر پیام پایدار است؛ خطای یک گیرنده مانع ارسال به بقیه نمی‌شود و پیام معیوب ابتدای صف، پیام‌های بعدی را برای همیشه مسدود نمی‌کند. خطای محدودیت ارسال با `retry_after` رعایت می‌شود؛ خطاهای توکن، دسترسی و Chat ID بدون نمایش توکن گزارش می‌شوند. قطعی پاسخ بعد از پذیرش پیام ممکن است همچنان به اعلان تکراری منجر شود؛ تضمین exactly-once وجود ندارد. خطای تلگرام مسیر اجرای سفارش را متوقف نمی‌کند.

برای اجرای محلی بدون هیچ ارسال تلگرام، `Telegram__DeliveryEnabled=false` را در `.env` بگذارید؛ صف حذف نمی‌شود. فعال‌کردن دوباره ممکن است اعلان‌های ذخیره‌شدهٔ قدیمی را هم ارسال کند.

## سابقه و کارنامهٔ معاملات

صفحهٔ «معاملات» علاوه بر معاملات باز، جدول مستقل معاملات بسته‌شده و آمار جداگانهٔ هر حساب/سرور/ارز دارد. رکوردهای تأییدشده در SQLite باقی می‌مانند؛ بسته‌شدن معامله یا راه‌اندازی مجدد، آن‌ها را از سابقه حذف نمی‌کند. ردیف‌های قدیمی‌تر صفحه‌بندی می‌شوند و خروجی کامل JSONِ سابقهٔ ثبت‌شده در دسترس است. این خروجی اطلاعات مالی دارد و برای انتشار عمومی باید ابتدا بازبینی شود.

در جزئیات، قیمت واقعی ورود و خروج، آخرین استاپ/هدف، ساعت سرور بروکر، حجم، سود بدون هزینه، کمیسیون، سواپ و نتیجهٔ خالص نمایش داده می‌شوند. برای سفارش‌های جدید، علت سیگنال و پارامترهای زمان ارسال هم ثبت می‌شوند؛ این‌ها از نتیجهٔ معامله حدس زده نمی‌شوند. داده‌های قدیمیِ فاقد قیمت خروج یا تفکیک هزینه، «—» دارند تا EA جدید آن‌ها را از بروکر بازیابی کند. مجموع ارزهای متفاوت یا حساب‌های دمو و واقعی با هم جمع نمی‌شوند.

**پس از این ارتقا EA را دوباره کامپایل کنید.** در MT4، داخل تب **Account History** راست‌کلیک و **All History** را انتخاب کنید. بازیابی فقط تاریخچه‌ای را می‌بیند که متاتریدر واقعاً بارگذاری کرده و Magic Number آن با EA یکسان است. هر سیکل یک صفحهٔ محدود خوانده می‌شود؛ برای سابقهٔ زیاد، تکمیل همگام‌سازی زمان می‌برد. بازیابی معامله‌های قدیمی، اعلان تلگرام قدیمی تولید نمی‌کند. اطلاعات ذخیره‌شده در برنامه، به‌تنهایی اثبات کامل‌بودن کل سابقهٔ بروکر یا سودآوری آینده نیست.

ژورنال، تاریخ و ساعت کامل ثبت رویداد و خلاصهٔ ساخت‌یافتهٔ معامله دارد؛ دکمهٔ «رویدادهای قدیمی‌تر» محدودیت نمایش آخرین ۱۰۰۰ رویداد را رفع می‌کند. زمان رویداد، زمان ثبت برنامه است؛ زمان معامله، ساعت سرور بروکر است. خروجی ژورنال شامل ردیف‌های بارگذاری‌شده است.

## بررسی‌ها

    scripts\dotnet.cmd build Trader.sln

طبق درخواست مالک، پروژه‌ها و فایل‌های تست جداگانه حذف شده‌اند و بدون درخواست صریح دوباره ساخته نمی‌شوند. بررسی تغییرات با بیلد و بازبینی انجام می‌شود. اجرای MT4 و بازبینی بصری مرورگر نیاز به ابزار‌های مربوط دارند.

فایل‌های توزیع‌شدنی از secrets پاک شده‌اند، ولی مالک باید Bot Token و PAT قبلی را rotate کند. تاریخچه‌ی Git بازنویسی و توکن‌ها revoke نشده‌اند.
